# Brainstorm

Ideas before they become project work: questions, rough plans, half-checked calculations,
reading notes. Messy is fine here. Nothing in this directory is a claim of the project.

## Layout

The same layout as the project, on a smaller scale, with its own graph:

| path | what |
|---|---|
| `context.md` | the state of the brainstorm now: open ideas, next step. ≤200 lines |
| `tasks/<id>/` | one idea worked on over more than one session, made with `opsci task new <id> --root brainstorm` |
| `verifications/<vid>/`, `tasks/<id>/verifications/<vid>/` | verification tasks of brainstorm work, made with `opsci task new <vid> --verifies <id>...` (`tasks/README.md` of the project, "Verification tasks") |
| `map/README.md` | how the ideas relate, hand-written, ≤150 lines |
| `map/graph.md`, `map/dead_ends.md` | the brainstorm nodes alone, GENERATED by `opsci map build`; never edit |
| `log/YYYY-MM.md` | append-only brainstorm log |

Node headers use the same schema as the project (`tasks/README.md` of the project). Start
brainstorm ids with `b` and a number (`b03-new-estimator`), so that they are never confused
with project task ids. The brainstorm nodes are part of the project graph: the project's
`map/graph.md` draws them in a box of their own, and an edge (`depends_on`, `related`,
`supersedes`) may join a brainstorm node and a project node in either direction. The project's `PROJECT.md`,
`rules/` and `citations/` apply here too; there are no separate copies.

## Not published

This directory is soft-private (`AGENTS.md` §6): `publish/manifest.yaml` does not include
it, so no file in it is released. A brainstorm task is soft-private by default
(`opsci task new` gives it `privacy: soft-private`). The public project map still names
each soft-private brainstorm node, without a link; at publish time the agent groups or
rewords the ones whose title or summary give too much away.

To publish some ideas, the user adds `- path: brainstorm` under `include` and sets
`privacy: public` in the header of each task to publish. The other tasks stay private.

So that the public project has no broken links, **nothing outside `brainstorm/` links to a
file here** (the generated `map/graph.md` excepted). A mention in passing, in backticks, is allowed. A reference in the other
direction, from here to the project, is fine.

Material that must not appear in the release even by name (proprietary data, collaborators'
unpublished work, private information about people) is hard-private: give its task
`privacy: hard-private` (`opsci task new <id> --root brainstorm --privacy hard-private`), or
list its path under `hard_private:` in `publish/manifest.yaml`.

## When an idea graduates

An idea becomes project work through a new project task (`opsci task new`, without
`--root`) that **restates** the idea in its own `context.md` or `plan.md`: the question,
what was found here, and the evidence, copied or rewritten so that the task stands alone.
The task does not link to this directory. Then set the brainstorm node's `status` to `done`
and name the new project task in its `summary`.
